# Windows overlay

The desktop has two native windows: `main` is the control panel and collaborative editor; `overlay` is a compact editor for the same live document. The retained debug LAN mode adds embedded session hosting to the control panel; the overlay never starts or manages the listener. The overlay has no editor toolbar and shows the same named remote cursors and colored selections as the regular document view. A compact, scrollable participant strip shows names, participant colors, and the same typing, selection, in-document and away activity as the control panel. The main window relays sanitized participant snapshots and remote awareness initially and whenever network awareness updates; departing participants disappear and leaving clears the strip and cursor decorations. Presence is visible in click-through mode and hidden while displaying the capture test card. Start and join a session in the control panel, then show the overlay. Disable click-through to write in it.

The main window owns the collaboration network connection; normal sessions use WebRTC peers, while the retained debug LAN mode uses an authenticated WebSocket. A desktop-only native relay sends initial Yjs state and subsequent incremental updates between the two WebViews. Independent CRDT replicas preserve simultaneous edits. Each editor keeps its own local cursor and activity; the active editor publishes through the main participant's network awareness identity. This prevents a blurred control-panel editor from clearing an overlay selection, and opening the overlay does not add a participant. Remote awareness updates reach both editors separately. Leaving clears the overlay; rejoining binds a fresh replica. No credentials pass through this relay, and documents and presence are not stored with preferences. Relay commands run off the UI thread to avoid startup IPC blocking native window creation; frontend queues preserve message order.

Desktop React code calls typed Tauri commands and listens for `overlay-changed`. Shared React accepts a control slot and contains no Tauri or Windows imports. Rust exposes the specification's `OverlayCapabilities` contract. Windows supports transparency, always on top, and click-through. The overlay has a capture-exclusion preference enabled by default and runtime supported/unsupported/unknown capability. The native adapter checks the actual OS build and desktop composition, sets display affinity only on this process's overlay HWND and verifies readback. A separate disabled/applied/unsupported/error status reports the outcome without claiming recorder compatibility. Other platforms report unsupported controls; they have not been runtime-tested. See [capture compatibility](capture-compatibility.md).

The Windows adapter keeps native layered-window alpha at 100% and manages z-order and cursor-event controls. Window opacity (0–100%) fades only a separate WebView background layer and its outer border. Text opacity (0–100%, default 100%) independently fades overlay document content, including its collaboration decorations. At 0% window opacity, document text retains its selected opacity. Header controls, participant activity, and the capture test card remain visible. Neither slider changes document appearance in the control panel or on another device. Existing settings retain their saved window opacity as background opacity; text defaults to 100%.

Slider values update immediately while preference writes run serially, coalescing pending values. A native acknowledgment cannot overwrite a newer drag value, and sliders stay enabled throughout the gesture. Opacity and font-size changes avoid native window style calls. Showing a window or changing toolkit styles can replace extended styles, so native alpha is restored to 100% after those operations, including capture-surface refreshes. Real compositor sampling is part of native acceptance; reading a successful API result alone is insufficient.

By default, Ctrl+Alt+V restores interaction, shows the overlay, and brings back the control panel. Ctrl+Alt+Shift+V toggles visibility. Shortcuts are registered natively and work outside the WebView. If the recovery shortcut is unavailable at startup, click-through is disabled and its saved preference is cleared. The system tray icon also reopens the control panel with a left click or **Open Veil** in its menu.

**Settings > Keybinds** lets you rebind New document, Join with a link, Copy invite link, Close document, Restore controls, and Show / hide overlay. Select a shortcut button and press Ctrl or Alt, optionally with Shift, plus a letter, number, or F1-F12. Escape cancels capture; Tab cancels and moves focus. Bindings use physical keys consistently with native global shortcuts. Each action needs a unique combination. Changes save on this device and update shortcut hints in both windows. Each action has a Reset button; Reset all keybinds restores the defaults. New document and Join with a link work from both the start screen and an open document in the control panel. From an open document, they ask for confirmation before closing it and creating a new document or opening the join form. Cancel preserves the current document and connections. Copy invite link and Close document run while their document is open. Open, Save, and Save As also have configurable document shortcuts. New and Join create tabs without replacing current documents. App keybinds take priority over editor shortcuts and pause while a dialog is open. Only Restore controls and Show / hide overlay are global. Replacement global shortcuts are acquired before old registrations are retired; an unavailable replacement leaves the previous bindings active. A global shortcut unavailable at startup can be changed individually, and the tray remains available for recovery. WebView2 browser accelerators are disabled in both desktop windows so Ctrl+J does not open Downloads, and browser commands do not compete with custom bindings. DOM key events and standard text-editing shortcuts remain available.

Settings include physical pixel bounds, window and text opacity, topmost, click-through, font size, and visibility. They are validated and stored separately from documents in the app's configuration directory. Writes use a temporary file in the same directory followed by atomic replacement. Move/resize saves are debounced by 250 ms; clean shutdown flushes the current values. Corrupt or incompatible settings restore defaults with a visible message. Monitor work areas constrain saved bounds after monitor removal. Window events query current bounds to avoid replaying stale startup positions.

Native window-setting commands require the `main` window. The overlay can read settings, initiate its own drag/resize, and relay document updates and ephemeral editor presence to the main window. The relay accepts only the two known window labels and bounds message size. Capabilities permit local event subscriptions only. Click-through cannot be enabled without a registered recovery shortcut. **Settings → General → When closing the main window** saves a device-local choice between **Minimize to tray** (default for new and existing settings) and **Quit app**. Minimizing preserves the document, connections and current overlay visibility; a hidden overlay stays hidden. Quit app resolves unsaved documents with Save / Discard / Cancel before closing both windows. **Quit Veil** in the tray follows the same workspace flow, regardless of the close preference. Cancelling keeps all tabs and sessions open; completing quit ends their sessions. Native quit administration is restricted to the control panel and refuses during update installation. The tray's **Show overlay / Hide overlay** action toggles only the overlay, and its label follows changes from Settings and shortcuts too.

## Verification

The overlay has square corners and a **×** button in its header to hide it without
ending the document or session. Right-click anywhere inside the overlay
and choose **Hide overlay**, the only context-menu option. Right-click the main
document and choose **Show overlay** to bring it back. Editing keyboard shortcuts
remain available. Both menus use the same app styling and follow the light/dark
theme, with square corners, matching icons and an accent hover/focus state.
With capture exclusion enabled, hovering the overlay close button or its menu
action keeps the default arrow cursor; their visual hover highlights remain.
The menu stays within its window; Escape, an outside click, scrolling, resizing,
or the window losing focus dismisses it. Enter or Space activates the focused action.
You can also show it from the control panel, the tray,
or Ctrl+Alt+Shift+V. Ctrl+Alt+V also restores interaction. In click-through mode,
use these recovery controls before clicking the button. The overlay can hide
itself; showing it and changing settings remain control-panel operations.

```powershell
pnpm --filter @veil/desktop tauri build --debug --no-bundle
pnpm test:overlay
node scripts/test-tray-close.mjs
```

Run on an interactive Windows desktop, close other Veil instances, and avoid moving the mouse during the test. Ports 4445, 9223 and 9224 must be free. The script starts an embedded session through the desktop controls and uses its bundled browser editor. The debug executable honors `VEIL_TEST_SETTINGS_DIR` solely for test isolation; release builds use the normal app configuration directory. The test process uses isolated WebView2 profiles and enables loopback remote debugging through its own environment.

The test connects Playwright to actual WebView2 targets and uses OS input and Win32 inspection. It verifies continuous native mouse drags of all three sliders, bidirectional control-panel/overlay/browser editing, concurrent convergence, cursor/selection presence with one desktop identity, reconnect, leave/rejoin, separate windows, keyboard-operated settings, real drag/resize, window opacity down to 0%, independent text opacity, compositor blending over another process, click interception/passthrough, global recovery and hide/show, atomic settings writes, non-default preferences after restart, and shortcut-collision rejection in both UI and Rust. Screenshots and isolated settings are saved under `target/overlay-acceptance`.

Unit tests cover atomic replacement, missing/corrupt files, invalid settings, and bounds fitting with removed and negative-coordinate monitors. Browser collaboration tests remain independent.

Multi-monitor/DPI hardware combinations and assistive technologies need a broader manual matrix. Capture compatibility is tracked separately in the linked results. Documents remain temporary. Installer and upgrade acceptance records, including unverified clean-machine checks, are documented in [testing](testing.md).
